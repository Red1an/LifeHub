# LifeHub

Личный хаб маленьких приложений («модулей») для жизни: финансы, заметки, привычки, тренажёр гитары и всё,
что вы сделаете сами с помощью нейронки. Хаб работает на вашем компьютере, открывается в браузере на компьютере
и на телефоне, а данные везде одни и те же.

## Запуск

Нужен Node.js 22.18+ (проверено на 24) и git.

```bash
npm install
npm start
```

Откройте http://localhost:4200. При первом запуске в `~/.lifehub/modules` копируются встроенные модули.

| Команда | Что делает |
|---|---|
| `npm start` | запустить хаб (порт 4200, `-- --port 5000` — другой) |
| `npm start -- --https` | HTTPS с самоподписанным сертификатом (для микрофона на телефоне) |
| `npm run dev` | режим разработки хаба: пересборка платформы при изменениях |
| `npm run check -- <id>` | проверить, что модуль собирается и типы в порядке (`all` — все) |
| `node bin/lifehub.mjs new <id> --name "…" --template collection` | создать модуль из шаблона |
| `node bin/lifehub.mjs password` | задать пароль для входа с телефона |
| `node bin/lifehub.mjs autostart on` / `off` | запускать хаб в фоне при входе в систему |
| `node bin/lifehub.mjs start --background` | запустить в фоне без окна (лог: `~/.lifehub/logs/hub.log`) |

Если PowerShell пишет «выполнение сценариев отключено», используйте `node bin/lifehub.mjs` вместо `npm start`.
Папку данных можно сменить переменной `LIFEHUB_HOME`.

## Работа в фоне

**Настройки → Работа в фоне → «Запускать при входе в Windows»** — хаб будет стартовать сам, без окна
терминала, и перезапускаться при сбое. Кнопка «Перевести в фон» переводит уже запущенный из терминала хаб
в фон, после чего терминал можно закрыть. Там же — перезапуск, остановка и лог.

## С телефона

**Дома (Wi‑Fi):**
1. На компьютере: **Настройки → Доступ с телефона** → задайте пароль.
2. На телефоне в той же сети отсканируйте QR-код и войдите по паролю.
3. «Добавить на главный экран» — и хаб выглядит как приложение.

**Вне дома — через [Tailscale](https://tailscale.com)** (бесплатная личная сеть ваших устройств):
1. Установите Tailscale на компьютер и на телефон, войдите в один аккаунт.
2. **Настройки → Доступ вне дома → «Включить адрес»** — хаб сам настроит `https://<компьютер>.<сеть>.ts.net`.
3. Откройте этот адрес на телефоне (QR-код там же). Настоящий HTTPS — работает и микрофон.

Хаб виден только вашим устройствам в Tailscale, порты на роутере открывать не нужно. Вход — по паролю хаба.

## Нейронка в модулях

Модули с разрешением `ai` могут обращаться к Claude через ваш **Claude Code** на компьютере с хабом —
без API-ключа, под вашим аккаунтом (идея из [«Звукоряда»](https://github.com/NIKFIRE4/NIKFIRE_plagin_diction_trainer)).
Один раз: установите Claude Code, выполните в терминале `claude` и войдите. Проверка — **Настройки → Нейронка
для модулей → «Проверить запрос»**. Claude запускается без доступа к файлам: только текст.

## Как сделать свой модуль

Модуль — это папка с `lifehub.json` и исходниками в `src/`. Писать код руками не обязательно:
модули делаются нейронкой.

### Через любую нейронку (ChatGPT, Claude и т.п.)

1. Откройте [docs/ПРОМПТ_ДЛЯ_МОДУЛЯ.md](docs/ПРОМПТ_ДЛЯ_МОДУЛЯ.md) и скопируйте в чат всё, что ниже линии.
2. В конце, после «МОЯ ЗАДАЧА», опишите модуль: что делает, какие экраны, что хранить, нужен ли виджет.
   Чтобы доработать готовый модуль — вставьте туда же его файлы и напишите, что изменить.
3. Разложите файлы из ответа в папку `~/.lifehub/modules/<id>` (id — из `lifehub.json`)
   или упакуйте в zip и установите: **Модули → Добавить → Из файла**. Хаб подхватит модуль сам.
4. Если модуль не собирается — в хабе есть кнопка «Скопировать для Claude Code» с текстом ошибки:
   вставьте его в тот же чат, нейронка исправит.

### Через Claude Code (удобнее всего)

Откройте в Claude Code папку `~/.lifehub/modules` (или папку одного модуля) и опишите задачу.
Там уже лежит полное руководство — [docs/MODULE_GUIDE.md](docs/MODULE_GUIDE.md), хаб копирует его как
`LIFEHUB_GUIDE.md`, — поэтому Claude Code знает SDK, сам проверяет сборку
(`node bin/lifehub.mjs check <id>`), а хаб пересобирает модуль сразу после сохранения файлов.
Быстрый старт: **Модули → Добавить → Создать** — модуль из шаблона, дальше всё в Claude Code.

### Поделиться модулем

- **Файлом:** на странице модуля — «Поделиться (zip)».
- **Через GitHub (с обновлениями):** выложите папку модуля в репозиторий (`lifehub.json` в корне или
  в подпапке — тогда ссылка вида `https://github.com/you/repo#папка`). Другие ставят его через
  **Модули → Добавить → По ссылке**. Чтобы выпустить обновление — повысьте `version` в `lifehub.json`
  и сделайте `git push`: у всех появится обновление, а их собственные правки модуля сольются с вашими.
  Сообщения коммитов пользователи увидят как список изменений.
- **Каталогом:** соберите свои модули в JSON-каталог (формат ниже) — друзья подключат его в настройках.

## Как это устроено

```
LifeHub/                  ← этот репозиторий (сам хаб)
  server/                 сервер: сборка модулей, кэш библиотек, данные, доступ
  platform/               браузер: оболочка хаба + SDK для модулей (@lifehub/sdk)
  modules/                встроенные модули (копируются пользователю при первом запуске)
  templates/              шаблоны новых модулей
  docs/MODULE_GUIDE.md    руководство по модулям — для людей и для Claude Code

~/.lifehub/               ← данные пользователя
  modules/<id>/           модули: только исходники, без node_modules
  libs/pkgs/<пакет>@<версия>/   общий кэш npm-библиотек
  data/lifehub.db         все данные модулей (SQLite)
  data/files/             файлы модулей (фото, записи)
  settings.json           настройки, хэш пароля
```

### Почему библиотеки не дублируются

Библиотеки делятся на три уровня:

1. **Платформа.** React и `@lifehub/sdk` живут в `platform.js` в одном экземпляре. Модуль, который делает
   `import { useState } from "react"`, получает общий React через `globalThis.__LIFEHUB__`
   (см. `server/shared.ts`), поэтому в браузере их нет в каждом модуле.
2. **Общий кэш npm.** Если модулю нужен пакет, он пишет его в `deps` манифеста. Хаб один раз скачивает
   `пакет@версия` в `~/.lifehub/libs` и собирает из него ESM-файл. Все модули, которым подходит эта версия,
   импортируют его по одному URL (`/libs/marked@16.4.2/index.js`), поэтому браузер загружает и кэширует
   его один раз. Неиспользуемые версии удаляются кнопкой в настройках.
3. **Модули-библиотеки.** Общий код ваших модулей (например, `audio` из GuitarHub: микрофон, высота тона,
   метроном) выносится в модуль с `"type": "library"`. Другие модули подключают его через
   `"uses"` и `import … from "@modules/audio"`.

Модуль компилируется esbuild на лету (за миллисекунды), и при сохранении файла хаб пересобирает его и
обновляет все открытые браузеры, включая телефон.

### Данные отдельно от кода

Модуль не трогает localStorage или файлы напрямую, а работает через SDK: `useCollection`, `useStore`, `files`.
Данные лежат в SQLite хаба с изоляцией по модулю. Поэтому модуль можно переписать, форкнуть или обновить,
и данные останутся на месте. Изменения сразу приходят на все устройства (SSE).

### Делиться и переделывать

- **Поделиться:** кнопка «Поделиться (zip)» на странице модуля или git-репозиторий с `lifehub.json`.
- **Установить:** Модули → Добавить: каталог, ссылка на git, zip, папка. Перед установкой показываются
  разрешения и библиотеки.
- **Дописать под себя:** откройте папку модуля в Claude Code и опишите, что поменять — можно править прямо
  установленный модуль. «Сделать свою версию» нужна, только если хотите держать рядом и оригинал.
- **История версий:** хаб сохраняет модуль после каждой удачной сборки (отдельный git в `~/.lifehub/history`).
  На странице модуля — список версий с изменениями и кнопка «Вернуть».
- **Обновления от автора:** модули из git следят за репозиторием автора — хаб проверяет его при запуске и
  каждые 6 часов и показывает список изменений. Если вы модуль не меняли — он заменяется. Если меняли —
  изменения автора сливаются с вашими автоматически (git, трёхстороннее слияние). Если вы с автором поменяли
  одни и те же строки, версия автора ложится в `.upstream/`, а объединяет Claude Code. Можно включить
  автообновление для модуля. Своя версия (форк) модуля из git тоже получает обновления автора.
- **Выпустить обновление своего модуля:** поменяйте `version` в `lifehub.json` и сделайте `git push` —
  у всех, кто поставил модуль по ссылке, появится обновление. Сообщения коммитов они увидят как список изменений.

### Каталог модулей

Любой JSON по ссылке, подключается в настройках:

```json
{
  "title": "Мои модули",
  "modules": [
    { "id": "water", "name": "Вода", "icon": "💧", "description": "Трекер воды", "git": "https://github.com/user/lifehub-water" },
    { "id": "speech", "name": "Речь", "icon": "🗣️", "description": "Тренер речи", "git": "https://github.com/user/lifehub-modules#speech" }
  ]
}
```

### Безопасность

- С этого компьютера хаб открывается без пароля, с других устройств только после входа. Пока пароль не задан,
  внешний доступ закрыт. Пароль меняется только с этого компьютера.
- Изменяющие запросы требуют заголовок `X-LifeHub`, а «локальный» доступ проверяет Host.
  Это защита от чужих сайтов в браузере и от DNS rebinding.
- npm-пакеты ставятся с `--ignore-scripts`.
- Модули выполняются в одной странице с хабом. Разрешения из манифеста (`files`, `mic`, `read:<id>`)
  соблюдает SDK и сервер, но это договорённость, а не песочница: ставьте модули от тех, кому доверяете,
  или попросите Claude Code проверить код.
