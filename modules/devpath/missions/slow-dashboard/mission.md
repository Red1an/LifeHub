Главная страница личного кабинета собирает три блока из трёх сервисов: заказы за сегодня, погоду и новости.
Каждый отвечает примерно за 400 мс, а страница грузится больше секунды. В плохие дни ещё хуже:

- сервис новостей иногда отвечает 502, и тогда **вся** страница показывает ошибку, хотя заказы и погода в порядке;
- сервис погоды иногда «висит» по 10 секунд, и пользователь смотрит на крутилку;
- пользователь уходит со страницы, а запросы продолжают крутиться впустую.

---task
Перепиши `DashboardLoader.LoadAsync`:

- три сервиса по 400 мс — дашборд быстрее 700 мс;
- упавший сервис не роняет остальные: его блок пустой (`null` или пустой список), а имя (`orders`, `weather`, `news`) — в `Failed`;
- каждый сервис ждём не дольше `PerServiceTimeout` (1 секунда), потом считаем его упавшим;
- если отменил **вызывающий** (токен `ct`), метод бросает `OperationCanceledException`, а не прячет это в `Failed`;
- каждый сервис вызывается ровно один раз.

---primer Запустить сразу, ждать потом
`await` сразу после вызова ждёт, пока операция закончится, и только потом идёт дальше:

```csharp
var a = await GetAAsync(); // 400 мс
var b = await GetBAsync(); // ещё 400 мс — итого 800
```

Если операции независимы, их можно **запустить** все сразу, а **ждать** потом. `Task` — это уже идущая операция:

```csharp
var ta = GetAAsync();          // запустили
var tb = GetBAsync();          // запустили второй, первый уже идёт
await Task.WhenAll(ta, tb);    // ждём оба — итого ~400 мс
var a = await ta;              // уже готово, ждать не надо
```

Отмена в .NET — это `CancellationToken`. Вызывающий передаёт токен, операция проверяет его и бросает `OperationCanceledException`.
Таймаут — это тоже отмена, только по времени:

```csharp
using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(1)); // сам отменится через секунду
await http.GetAsync(url, cts.Token);
```

`CancellationTokenSource.CreateLinkedTokenSource(ct)` создаёт токен, который отменится, если отменили `ct` **или** его самого.

Почему три запроса по 400 мс дают больше секунды? И как отличить «сервис не ответил за секунду» от «пользователь ушёл со страницы», если оба — `OperationCanceledException`?

---hint
Посмотри, где стоят `await`: второй запрос начинается только после того, как закончился первый. Что, если сначала получить все три `Task`, а `await` сделать потом?

---hint
Нужна обёртка для одного блока: свой таймаут (связанный с `ct` токен + `CancelAfter`), `try/catch`, результат «удалось / не удалось + значение».
Чтобы понять, чей это был таймаут, проверь `ct.IsCancellationRequested` в фильтре исключения: `catch (OperationCanceledException) when (…)`.

---hint
Сделай `async Task<(bool Ok, T? Value)> Try<T>(Func<CancellationToken, Task<T>> call, CancellationToken ct)`: внутри `CreateLinkedTokenSource(ct)` + `CancelAfter(PerServiceTimeout)`,
ловишь `OperationCanceledException when (!ct.IsCancellationRequested)` и остальные исключения (кроме отмены) → `(false, default)`.
В `LoadAsync` вызови `Try` три раза без `await`, потом `await Task.WhenAll(...)`.

---debrief
## Почему было медленно

Последовательные `await` складывают время: 400 + 400 + 400. Три независимых запроса можно запустить одновременно — тогда время равно самому медленному.
Это самая частая и самая дешёвая оптимизация в веб-сервисах: найти независимые ожидания и перестать ждать их по очереди.

## Почему `WhenAll` без обёртки было бы мало

`Task.WhenAll` бросает исключение, если упала хотя бы одна задача, — и результат остальных проще потерять. Поэтому каждый блок обёрнут:
ошибка превращается в значение «не удалось», и `WhenAll` всегда завершается успешно. Это называется **изоляцией отказов**:
одна сломанная зависимость не должна ронять всю страницу (graceful degradation).

## Почему не `Task.Run` и не `Parallel.ForEach`

Ожидание ответа по сети не занимает процессор, поэтому отдельные потоки не нужны. `Task.Run` занял бы поток из пула
просто ради ожидания, а `Parallel.ForEach` создан для вычислений, а не для асинхронного I/O.
Для I/O — асинхронность (`async/await` + `WhenAll`), для тяжёлых вычислений — параллельность (`Parallel`, `Task.Run`).

## Свой таймаут и чужая отмена

Таймаут блока и уход пользователя внешне одинаковы — оба `OperationCanceledException`. Но смысл разный:
таймаут — «сервис плохой, покажем страницу без него»; отмена вызывающим — «страница больше никому не нужна, бросаем всё».
Если спрятать отмену в `Failed`, сервер будет дальше тратить ресурсы на ответ, который никто не увидит.

## Что дальше в реальной жизни

- **Бюджет времени.** Секунда на каждый сервис — это всё равно секунда на страницу. Иногда задают общий дедлайн.
- **Microsoft.Extensions.Resilience (Polly)** — готовые таймауты, повторы и circuit breaker. Писать вручную нужно, чтобы понимать, что они делают;
  в продакшене обычно берут библиотеку.
- **Кэш последнего удачного ответа**: показать вчерашнюю погоду лучше, чем пустой блок.

---recall
Q: Как ускорить несколько независимых await подряд?
A: Сначала запустить все операции (получить Task'и), потом await Task.WhenAll — время = самой медленной, а не сумме.

Q: Как сделать таймаут на асинхронную операцию с сохранением отмены вызывающим?
A: CancellationTokenSource.CreateLinkedTokenSource(ct) + CancelAfter(время); ловить OperationCanceledException when (!ct.IsCancellationRequested).

Q: Async или Parallel: что для чего?
A: Async/await — для ожидания I/O (сеть, диск, БД) без занятых потоков. Parallel/Task.Run — для вычислений на нескольких ядрах.
