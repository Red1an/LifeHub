После утренней рассылки «Скидки недели» пришло 300 жалоб: людям пришло **по два одинаковых письма**.
Почтовый сервис выставил счёт за двойной объём, а администратор БД пишет, что рассылка делает два одинаковых тяжёлых
запроса к таблице пользователей.

В коде всего несколько строк, и никакого цикла «отправить дважды» в нём нет. Ещё маркетологи просят: если человек
подписался дважды (`Anna@Mail.ru` и `anna@mail.ru`), письмо должно уйти одно.

---task
Почини `Newsletter.Send` в `src/Mailing/Newsletter.cs`:

- каждому подписчику — ровно одно письмо, метод возвращает число отправленных;
- пользователи читаются из репозитория **один раз**;
- адреса, которые отличаются только регистром или пробелами по краям, считаются одним.

---primer LINQ ленивый
Цепочка `Where`/`Select` ничего не выполняет сама по себе. Она лишь описывает, **как** получить элементы.
Работа начинается, когда кто-то перебирает результат: `foreach`, `ToList`, `Count`, `Any`, `First`…
И начинается **заново при каждом переборе**.

```csharp
var squares = numbers.Select(n =>
{
    Console.WriteLine($"считаю {n}");
    return n * n;
});
// пока ничего не напечатано

var a = squares.Count();  // «считаю 1», «считаю 2», …
var b = squares.Sum();    // и снова «считаю 1», «считаю 2», …
```

`ToList()` / `ToArray()` выполняют запрос один раз и сохраняют результат — дальше работа идёт с готовым списком.

```csharp
var list = numbers.Select(n => n * n).ToList(); // посчитали один раз
var a = list.Count;   // без пересчёта
var b = list.Sum();   // без пересчёта
```

---hypothesis
Где в коде письмо отправляется второй раз, если явного повтора нет? Подсказка в слове «ленивый». Сколько раз выполняется лямбда в `Select`?

---hint
Посчитай, сколько раз перебирается `sent`: что делает `Any()`, а что `Count()`? И что происходит с лямбдой внутри `Select` при каждом переборе?

---hint
`Any()` перебирает до первого элемента — и отправляет первое письмо. `Count()` перебирает всё заново — отправляет всем ещё раз.
Получить данные и отправить письма — это два разных шага. Как сделать, чтобы данные получились ровно один раз?

---hint
Сначала собери адреса: `Where` → `Select(нормализованный email)` → `Distinct()` → `ToList()`. Потом обычный `foreach` с отправкой,
и верни `Count` списка. Нормализация: `Trim()` и `ToLowerInvariant()`.

---debrief
## Что происходило

`sent` — не список писем, а **рецепт**. `Any()` выполнил его до первого элемента (одно письмо ушло),
`Count()` выполнил с начала (ушли все, включая первое ещё раз). Заодно каждый перебор начинал `users.All()` заново —
отсюда два запроса к базе. С `IQueryable` в EF Core то же самое: каждый перебор — отдельный SQL-запрос.

## Почему побочные эффекты не место в Select

`Select` — это «преобразовать», и читатель ожидает, что он ничего не меняет в мире. Когда внутри него отправка письма,
запись в базу или увеличение счётчика, поведение зависит от того, **сколько раз и когда** перебрали результат.
Это сложно увидеть на ревью. Правило: запросы в LINQ, действия — в `foreach`.

## Когда ленивость — это хорошо

Не стоит лепить `ToList()` везде «на всякий случай»:

- **Большие данные.** `File.ReadLines` + `Where` обрабатывает файл на 10 ГБ построчно, не загружая его в память.
  `ToList()` уронил бы процесс.
- **Ранний выход.** `items.Where(…).First()` останавливается на первом совпадении. Материализация перебрала бы всё.
- **Построение запроса.** В EF Core условия можно добавлять по шагам (`if (filter) q = q.Where(…)`) — SQL соберётся один раз в конце.

Материализуй, когда результат нужен **больше одного раза** или когда нужна точка «данные получены» перед действиями.

## Почему `ToLowerInvariant`, а не `ToLower`

`ToLower()` зависит от языка системы. В турецкой локали `"I".ToLower()` — это `ı` без точки, и `ADMIN@MAIL.RU` превратится не в то,
что ожидалось. Для технических строк (email, ключи, коды) — всегда `Invariant` или `StringComparer.OrdinalIgnoreCase`.
Альтернатива нормализации: `DistinctBy(u => u.Email.Trim(), StringComparer.OrdinalIgnoreCase)` — сохранит исходное написание адреса.

---recall
Q: Что значит «LINQ выполняется отложенно»?
A: Цепочка Where/Select — только описание; выполняется при переборе (foreach, ToList, Count, Any…) и заново при каждом переборе.

Q: Почему нельзя делать побочные эффекты (отправку, запись) внутри Select?
A: Они выполнятся столько раз, сколько раз перебрали результат — легко получить дубли или ничего. Действия — в foreach.

Q: Когда ленивость LINQ полезна?
A: Огромные данные (построчная обработка без загрузки в память), ранний выход (First/Any), пошаговое построение запроса EF Core.
