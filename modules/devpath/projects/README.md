# Большие проекты DevPath

Проект — система, которую ученик строит сам с нуля по этапам. Хаб выдаёт каркас в `~/DevPath/<id>`,
на каждом этапе кладёт свои тесты и инфраструктуру и проверяет **все открытые этапы сразу**: старое ломать нельзя.

## Устройство `projects/<id>/`

```
project.md            — вступление и дорожная карта (---stages: «NN | название | технологии»)
skeleton/             — каркас: решение (.slnx), пустой API с `public partial class Program`
hub/                  — общая часть тестов хаба: Hub.Tests.csproj, помощники (HubApp.cs)
infra/                — docker-compose.yml по умолчанию (поднимает хаб перед проверкой)
stages/NN/stage.md    — текст этапа (формат ниже)
stages/NN/tests/      — тесты хаба этапа → в рабочей папке hub/StageNN/
stages/NN/infra/      — новая инфраструктура с этого этапа (Redis, Kafka, Grafana…), если нужна
stages/NN/solution/   — эталон ВСЕГО проекта на этом этапе (накладывается на skeleton)
```

Правила тестов:
- имя каждого теста — `DisplayName = "ЭN.xx …"`: по префиксу экран делит тесты на этот этап и прошлые;
- тесты ходят в приложение только через HTTP (WebApplicationFactory) и контракт из stage.md, а не через внутренние классы ученика —
  иначе его решение должно было бы совпасть с эталоном по устройству;
- база — своя на каждый тест (`ExchangeApp`), удаляется после; порты инфраструктуры — 1xxxx (ниже динамического диапазона Windows 49152+, где Hyper-V резервирует порты), чтобы не мешать чужому;
- свои тесты ученика (`tests/…`) хаб считает по сборке: всё, что не Hub.Tests. Требование — `ownTests` в stage.md.

Фронтенд (с этапа 5): папка `web/` ученика. Хаб перед тестами делает `npm install` (если поменялись зависимости) и
`npm run build` с `VITE_API_URL=http://127.0.0.1:15080`. Тесты (hub/Web.cs) поднимают API на этом порту через `UseKestrel`,
раздают `web/dist` на 15090 и открывают его в системном Edge через Playwright (`Channel = "msedge"`, браузер не скачивается).
Элементы — по `data-testid`, числа — из `data-*`. Тесты с котировками сначала чистят Redis (`ExchangeApp.FlushRedis()`).

Проверка этапов: `node server/devpath/verify.ts <id>` из корня хаба (нужен запущенный Docker):
эталон прошлого этапа не проходит тесты нового, эталон этапа N проходит тесты 1..N.

## stage.md

```
---
title: Движок сведения
topics: arch-ddd, dotnet-testing     ← id тем справочника
hours: 8                              ← оценка; от неё опыт за этап
ownTests: 8                           ← сколько своих тестов нужно (0 — не нужно)
---
Зачем этап: какая проблема и почему без этого нельзя.

---task
Контракт: что должно работать (это проверяют тесты).
---design
Вопрос «как спроектируешь» — ученик отвечает до кода.
---primer Заголовок
Разобранный пример на другом коде.
---steps
План по шагам.
---hint      (×3: вопрос → направление → почти решение)
---break
Эксперименты «сломай и посмотри».
---debrief
## Разделы разбора: почему так, альтернативы, как в продакшене
---quiz       (вопросы с собеседований, формат src/content/README.md)
---recall     (Q:/A: → в карточки)
```

Новый этап добавь в `src/data/projects-build.ts`.
