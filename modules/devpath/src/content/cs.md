# @cs-complexity

## O-нотация
O(f(n)) — верхняя граница роста времени (или памяти) при увеличении входа. Константы и младшие члены отбрасываются: `3n² + 10n` → O(n²).

| Сложность | Пример | n = 1 000 000 |
|---|---|---|
| O(1) | доступ по индексу, поиск в хэш-таблице | мгновенно |
| O(log n) | бинарный поиск | ~20 шагов |
| O(n) | проход по массиву | 10⁶ |
| O(n log n) | хорошая сортировка | ~2·10⁷ |
| O(n²) | вложенные циклы | 10¹² — часы |
| O(2ⁿ) | перебор подмножеств | невозможно |

Θ — точная оценка, Ω — нижняя. На собеседовании обычно говорят «O» в смысле точной оценки худшего случая.

## Амортизированная сложность
Операция иногда дорогая, но в среднем по последовательности — дешёвая. Добавление в `List<T>`: изредка копирование массива O(n), но амортизированно O(1), потому что ёмкость удваивается.

## Оценка по ограничениям
Современный компьютер делает ~10⁸ простых операций в секунду. По ограничениям задачи можно угадать нужный алгоритм:
- n ≤ 20 → перебор O(2ⁿ);
- n ≤ 1000 → O(n²);
- n ≤ 10⁵–10⁶ → O(n log n) или O(n);
- n ≤ 10⁹ → O(log n) или O(1).

Не забывайте о **памяти**: рекурсия глубины n занимает O(n) стека; копирование подмассивов на каждом шаге — скрытый O(n²).

# @cs-arrays

## Хэш-таблица — первый инструмент
Половина задач решается словарём: подсчёт частот, поиск пары, группировка, дубликаты.
```csharp
// Two Sum: индексы двух чисел с заданной суммой, O(n)
int[] TwoSum(int[] a, int target)
{
    var seen = new Dictionary<int, int>();
    for (int i = 0; i < a.Length; i++)
    {
        if (seen.TryGetValue(target - a[i], out var j)) return [j, i];
        seen[a[i]] = i;
    }
    return [];
}
```

## Два указателя
Для **отсортированных** массивов или когда нужно сравнивать элементы с разных концов: сумма пары в отсортированном массиве, разворот, удаление дубликатов на месте, «контейнер с водой». Указатели идут навстречу или один догоняет другой — O(n) вместо O(n²).

## Скользящее окно
Подмассив/подстрока с условием: «самая длинная подстрока без повторов», «минимальное окно, содержащее все символы». Правую границу двигаем всегда, левую — когда окно нарушает условие. Каждый элемент входит и выходит один раз → O(n).

## Префиксные суммы и сортировка
- `prefix[i] = a[0] + … + a[i-1]` → сумма любого отрезка за O(1): `prefix[r] - prefix[l]`. Вариант: «число подмассивов с суммой k» — префиксы + словарь.
- Сортировка часто упрощает задачу (интервалы, анаграммы). `Array.Sort` в .NET — introsort, O(n log n), нестабильная; `OrderBy` в LINQ — стабильная.

Q: Когда применять технику двух указателей и когда скользящее окно?
A: Два указателя — когда массив отсортирован или нужно сравнивать элементы с двух концов (пары, разворот, слияние). Скользящее окно — когда ищем непрерывный подмассив/подстроку с условием: окно расширяется справа и сжимается слева.

# @cs-structures

## Стек и очередь
- **Stack** (LIFO): скобочные последовательности, обход в глубину, отмена действий, вычисление выражений.
- **Queue** (FIFO): обход в ширину, буферы, планирование.
- **Монотонный стек** — «следующий больший элемент», «наибольший прямоугольник в гистограмме» за O(n).

## Куча
Двоичная куча — дерево в массиве, где родитель не больше детей (min-heap). Вставка и извлечение минимума O(log n), минимум — O(1). В .NET — `PriorityQueue<TElement, TPriority>`.

Задачи: топ-K элементов (куча размера K), слияние K отсортированных списков, медиана потока (две кучи), алгоритм Дейкстры, планировщик задач.

## Связные списки
Вставка/удаление по известному узлу O(1), доступ по индексу O(n), плохая локальность кэша. Классика собеседований: разворот списка, поиск цикла (**быстрый и медленный указатель** Флойда), середина списка, слияние двух отсортированных.

## LRU-кэш
Словарь `ключ → узел` + двусвязный список по давности использования. Обращение — перенести узел в голову O(1); переполнение — удалить хвост O(1).
```csharp
// в .NET: Dictionary<TKey, LinkedListNode<(TKey, TValue)>> + LinkedList<(TKey, TValue)>
```

# @cs-trees

## Деревья
- **BST** — слева меньше, справа больше; поиск O(h). Сбалансированные (красно-чёрные, AVL) гарантируют h = O(log n) — так устроены `SortedDictionary`, `SortedSet`.
- **Обходы**: in-order (для BST даёт отсортированный порядок), pre-order, post-order, по уровням (BFS).
- **Trie** — префиксное дерево для строк: автодополнение, словари.

## Графы: BFS и DFS
```csharp
// BFS: кратчайший путь в невзвешенном графе
int Bfs(List<int>[] g, int start, int target)
{
    var dist = new int[g.Length]; Array.Fill(dist, -1);
    var q = new Queue<int>(); q.Enqueue(start); dist[start] = 0;
    while (q.Count > 0)
    {
        var v = q.Dequeue();
        if (v == target) return dist[v];
        foreach (var u in g[v]) if (dist[u] == -1) { dist[u] = dist[v] + 1; q.Enqueue(u); }
    }
    return -1;
}
```
- **BFS** — по слоям, кратчайшие пути без весов, «острова» в сетке.
- **DFS** — поиск циклов, компоненты связности, backtracking, топологическая сортировка.

## Классические алгоритмы
- **Топологическая сортировка** — порядок задач с зависимостями (сборка проектов, миграции); алгоритм Кана через входящие степени.
- **Дейкстра** — кратчайшие пути с неотрицательными весами, куча, O((V + E) log V).
- **Union-Find** (система непересекающихся множеств) — связность, «число компонент», алгоритм Краскала; почти O(1) на операцию.

# @cs-dp

## Идея
Динамическое программирование — решение через **подзадачи**, результаты которых переиспользуются. Применимо, если есть:
1. **оптимальная подструктура** — ответ собирается из ответов подзадач;
2. **перекрывающиеся подзадачи** — одни и те же подзадачи встречаются многократно.

## Рецепт
1. Определить **состояние**: что означает `dp[i]` (или `dp[i][j]`).
2. Записать **переход**: как `dp[i]` выражается через меньшие.
3. **Базу**.
4. **Порядок** вычисления и где ответ.

```csharp
// Число способов подняться на n ступенек шагами 1 или 2
long Climb(int n)
{
    long a = 1, b = 1;                  // dp[0], dp[1]
    for (int i = 2; i <= n; i++) (a, b) = (b, a + b);
    return b;                           // dp[i] = dp[i-1] + dp[i-2]
}
```

## Мемоизация и табуляция
- **Сверху вниз**: рекурсия + кэш результатов. Естественно записывается, но глубокая рекурсия.
- **Снизу вверх**: заполняем таблицу в правильном порядке. Часто можно хранить только последние строки (экономия памяти).

## Классические задачи
- **Рюкзак 0/1**: `dp[w]` — лучшая ценность при весе w.
- **LIS** — наибольшая возрастающая подпоследовательность (O(n²) или O(n log n)).
- **LCS / редакционное расстояние** — `dp[i][j]` по префиксам двух строк (diff, опечатки).
- **Пути в сетке**, размен монет, разбиение строки на слова.

A: Определить состояние (что значит dp[i]), записать формулу перехода через меньшие состояния, задать базу, выбрать порядок вычисления (мемоизация сверху вниз или табуляция снизу вверх), найти ответ и при необходимости оптимизировать память.

# @cs-search

## Бинарный поиск
Для отсортированного массива — O(log n). Главное — аккуратные границы:
```csharp
// первый индекс, где a[i] >= x (lower bound)
int LowerBound(int[] a, int x)
{
    int lo = 0, hi = a.Length;          // [lo, hi)
    while (lo < hi)
    {
        int mid = lo + (hi - lo) / 2;   // без переполнения
        if (a[mid] < x) lo = mid + 1; else hi = mid;
    }
    return lo;
}
```
В .NET: `Array.BinarySearch` (возвращает ~index, если не найдено), `List<T>.BinarySearch`.

## Поиск по ответу
Если ответ монотонен («если скорость v подходит, то и большая подходит»), можно бинарно искать **сам ответ**: минимальная вместимость для доставки за D дней, минимальная скорость поедания бананов, максимальное минимальное расстояние. Проверка кандидата — жадно за O(n).

## Жадные алгоритмы
На каждом шаге берём локально лучший вариант. Работает не всегда — нужно обоснование (или контрпример). Классика:
- **выбор максимума непересекающихся интервалов** — сортировка по концу и жадный выбор;
- слияние интервалов — сортировка по началу;
- размен монет — жадно только для «канонических» систем монет.

## Интервалы
Много задач — про интервалы: встречи в переговорках (min-heap по времени окончания), объединение, вставка интервала. Почти всегда начинаются с сортировки.

A: Если свойство «ответ X подходит» монотонно по X, можно бинарно искать минимальный (или максимальный) подходящий X, проверяя кандидата за O(n). Итог O(n log диапазона).

# @cs-os

## Процессы и потоки
**Процесс** — изолированное адресное пространство, ресурсы, минимум один поток. **Поток** — единица выполнения внутри процесса, делит память с другими потоками. Переключение контекста между потоками стоит микросекунды (сохранение регистров, сброс кэшей) — тысячи активных потоков тратят CPU на переключения.

## Виртуальная память
Каждый процесс видит своё виртуальное адресное пространство; ОС отображает страницы (обычно 4 КБ) на физическую память через таблицы страниц и TLB. Если страницы нет в памяти — **page fault**, её подгружают (с диска — очень медленно). Нехватка памяти → **swap** → всё тормозит; в Linux — **OOM killer** убивает процесс.

## Планировщик
ОС делит процессорное время между потоками (в Linux — CFS/EEVDF). Приоритеты, кванты времени, привязка к ядрам. В контейнерах лимит CPU реализуется через cgroups — при превышении поток **троттлится**.

## Модели ввода-вывода
- **Блокирующий** — поток ждёт завершения операции.
- **Неблокирующий + мультиплексирование** — один поток следит за множеством сокетов: `epoll` (Linux), `kqueue` (BSD/macOS), **IOCP** (Windows).
- .NET построен на этом: `async/await` + epoll/IOCP позволяют держать десятки тысяч соединений небольшим пулом потоков.

Q: Чем процесс отличается от потока?
A: Процесс — изолированное адресное пространство и набор ресурсов ОС; потоки внутри процесса разделяют память и ресурсы, но имеют свои стеки и регистры. Процессы изолированы друг от друга, потоки — нет, поэтому им нужна синхронизация.

# @cs-hardware

## Иерархия памяти
Примерные задержки:
- регистр ~0.3 нс, L1 ~1 нс, L2 ~4 нс, L3 ~15 нс;
- оперативная память ~100 нс;
- SSD ~100 мкс, сеть в дата-центре ~0.5 мс, HDD ~10 мс, межконтинентальный пакет ~150 мс.
Разница между L1 и RAM — два порядка. Поэтому **локальность данных** часто важнее O-сложности: проход по массиву быстрее прохода по связному списку той же длины.

## Cache lines и false sharing
Процессор загружает память линиями по **64 байта**. Если два потока пишут в разные переменные, лежащие в одной линии, ядра постоянно отбирают линию друг у друга — **false sharing**, производительность падает в разы. Лечение — выравнивание/паддинг (`[StructLayout]`, отдельные объекты), per-thread данные с объединением в конце.

## Предсказание переходов
Процессор угадывает, куда пойдёт условие, и выполняет наперёд. Непредсказуемые ветки (случайные данные) стоят ~15 тактов на промах. Отсюда классический пример: сумма элементов > 128 в отсортированном массиве считается в разы быстрее, чем в неотсортированном.

## SIMD
Одна инструкция обрабатывает сразу 4–16 чисел. В .NET — `Vector<T>`, `Vector128/256/512`, аппаратные интринсики. Многие методы BCL (поиск в Span, LINQ Sum/Min/Max, кодирование строк) уже векторизованы.

Q: Назови порядки задержек основных уровней памяти и хранения.
A: L1 ~1 нс, RAM ~100 нс, SSD ~100 мкс, сеть внутри ДЦ ~0.5 мс, HDD ~10 мс, между континентами ~150 мс. Каждый уровень примерно на порядки медленнее предыдущего.

# @cs-patterns

## Узнать тип задачи
Сильные кандидаты не решают каждую задачу с нуля, а **узнают паттерн**:
| Признак в условии | Паттерн |
|---|---|
| отсортированный массив, пара/тройка с суммой | два указателя |
| непрерывный подмассив/подстрока с условием | скользящее окно |
| цикл в списке, середина | быстрый/медленный указатель |
| «минимальное X, при котором возможно» | бинарный поиск по ответу |
| топ-K, K-й по величине, слияние K списков | куча |
| кратчайший путь, уровни, сетка | BFS |
| все варианты, перестановки, подмножества | backtracking (DFS) |
| зависимости, порядок | топологическая сортировка |
| связность, объединение групп | union-find |
| число способов, оптимум с подзадачами | DP |
| «следующий больший» | монотонный стек |

## Как вести себя на интервью
1. **Уточнить условие**: размеры, крайние случаи, дубликаты, пустой вход.
2. Проговорить **наивное решение** и его сложность.
3. Предложить оптимизацию, назвать паттерн, сложность.
4. Писать код **вслух**, с понятными именами.
5. **Протестировать** на примере и крайних случаях руками.
6. Обсудить улучшения.
Интервьюер оценивает мышление и коммуникацию не меньше, чем правильный ответ.

## Как тренироваться
Решайте **по темам** (NeetCode 150, Grokking patterns), затем вперемешку. Если застряли на 30–40 минут — смотрите разбор, а через несколько дней решайте заново без подсказки (интервальное повторение работает и здесь).
