# @onec-platform

## Глубже: архитектура платформы 1С
**Клиент-серверный режим**: кластер серверов 1С (менеджер кластера `rmngr`, рабочие процессы `rphost`) + СУБД (PostgreSQL или MS SQL). Сеансы пользователей распределяются по рабочим процессам; серверные вызовы идут в них, а данные — в СУБД через платформенный слой, который генерирует SQL.

**Хранение**: каждый объект метаданных — таблицы СУБД с системными именами (`_Reference42`, `_Document57`); прямая работа с ними запрещена лицензией и опасна; смотреть соответствие — `ПолучитьСтруктуруХраненияБазыДанных()`.

**Разработка**: конфигурации поставщиков на поддержке; хранилище конфигурации для командной работы в Конфигураторе; **EDT** — git, ветки, рефакторинги, проверки (АПК/стандарты). CI для 1С: сборка из исходников, Vanessa Automation (BDD-тесты), YAxUnit (юнит-тесты), SonarQube с BSL Language Server.

**Режимы запуска**: тонкий клиент, веб-клиент, мобильная платформа; **1С:Предприятие.Элемент** — облачная платформа нового поколения.

# @onec-language

## Глубже: качество кода на встроенном языке
**Стандарты 1С** — обязательное чтение: структура модулей (области `#Область ПрограммныйИнтерфейс`, `СлужебныйПрограммныйИнтерфейс`, `СлужебныеПроцедурыИФункции`), именование, обработка ошибок, работа с транзакциями.

**Транзакции**: `НачатьТранзакцию()` — `ЗафиксироватьТранзакцию()` в `Попытка…Исключение` с `ОтменитьТранзакцию()`; никаких интерактивных действий и внешних вызовов внутри; вложенные транзакции не независимы.

**Исключения**: `ВызватьИсключение` с понятным текстом; `ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())` в журнал регистрации.

**Производительность языка**: `Соответствие` для поиска вместо перебора массива; `ТаблицаЗначений` с индексами (`Индексы.Добавить`) для частого поиска; избегать создания объектов (`ПолучитьОбъект()`) там, где хватает запроса или реквизитов ссылки.

**Фоновые задания** и **регламентные задания** — асинхронная работа на сервере; длительные операции из форм — через БСП `ДлительныеОперации`.

**Асинхронность на клиенте**: `Асинх`/`Ждать` (8.3.18+) вместо `ОписаниеОповещения` для диалогов.

# @onec-queries

## Глубже: оптимизация запросов 1С
**Как платформа строит SQL**: разыменование `Документ.Контрагент.Родитель.Наименование` — цепочка LEFT JOIN; для составных типов — соединения с каждой возможной таблицей. Минимизируйте разыменования, используйте `ВЫРАЗИТЬ(... КАК Справочник.Контрагенты)`.

**Виртуальные таблицы**: условия в параметрах (`Остатки(&Дата, Склад = &Склад)`), таблицы итогов регистров (`Остатки` на дату — от ближайших рассчитанных итогов), пересчёт итогов.

**Временные таблицы**: индексирование (`ИНДЕКСИРОВАТЬ ПО`) при последующих соединениях; уничтожение (`УНИЧТОЖИТЬ`) в пакете.

**Условия**: `В (&Список)` с большим списком → временная таблица и соединение; `ИЛИ` в условиях мешает индексам — `ОБЪЕДИНИТЬ ВСЕ`; подзапросы в условиях соединения — источник медленных планов.

**Анализ**: технологический журнал (события DBPOSTGRS/DBMSSQL с планами), консоль запросов с выводом SQL, анализ плана в СУБД.

# @onec-registers

## Глубже: регистры и проведение правильно
**Новая методика контроля остатков**: сначала записать движения, затем проверить остатки запросом к регистру (отрицательные — отказ); проверка выполняется с управляемой блокировкой по измерениям — меньше блокировок, чем «проверить, потом списать».

**Итоги регистров**: регистр накопления хранит движения и таблицу итогов по периодам; разделение итогов (для параллельной записи), периодичность итогов, пересчёт, отключение итогов при массовой загрузке.

**Регистры сведений**: независимые (свои записи) и подчинённые регистратору; периодические — срез последних/первых; ключевые измерения и индексы.

**Регистр бухгалтерии**: проводки по плану счетов с субконто; остатки и обороты по счетам.

**Последовательности и перепроведение**: при изменении прошлых документов — восстановление последовательности; избегайте массового перепроведения в рабочее время.

**Партионный учёт**, **РАУЗ** в ERP — примеры сложной логики на регистрах.

# @onec-bsp

## Глубже: БСП и расширения на практике
**Подключение к БСП**: переопределяемые модули (`…Переопределяемый`) — точка настройки поведения подсистем без изменения их кода; программный интерфейс (`ОбщегоНазначения`, `ОбщегоНазначенияКлиентСервер`, `ДлительныеОперации`, `Пользователи`, `УправлениеДоступом`).

**Управление доступом** (RLS): ограничение доступа на уровне записей — шаблоны ограничений, наборы значений доступа; важно для производительности и безопасности.

**Расширения**: аннотации `&Перед`, `&После`, `&Вместо`, `&ИзменениеИКонтроль` (контроль изменения исходного метода — при изменении в обновлении получите ошибку, а не тихую поломку); добавление реквизитов, форм, подсистем; безопасный режим расширений; порядок применения нескольких расширений.

**Обновление**: при каждом обновлении типовой — проверка расширений (адаптация, `ИзменениеИКонтроль` помогает); автоматизация тестами Vanessa.

**Тиражные решения** на БСП — готовая инфраструктура: обновление ИБ, версионирование, печать, файлы, email, интеграции.

# @onec-forms

## Глубже: быстрые управляемые формы
**Клиент-серверные вызовы**: каждое обращение к серверу из формы — сетевой круг; объединяйте получение данных в один вызов при открытии (`ПриСозданииНаСервере`), используйте `&НаСервереБезКонтекста` и передавайте только нужное.

**Динамические списки**: запрос с порционной выборкой — быстро на больших таблицах; не загружайте тысячи строк в табличную часть формы.

**Условное оформление** вместо программного раскрашивания строк; **функциональные опции** для скрытия функциональности.

**СКД глубже**: наборы данных (запрос, объект, объединение), вычисляемые поля, ресурсы и их расчёт в группировках, параметры и отборы, пользовательские настройки и варианты отчётов, вывод в макет; программное формирование отчёта на сервере для рассылок.

**Печатные формы**: макеты табличных документов, подсистема Печать из БСП, вывод в PDF.

**Мобильные и веб-клиенты**: адаптивность форм, отсутствие модальности, ограничения веб-клиента.

# @onec-integration

## Глубже: надёжный обмен 1С с внешними системами
**Архитектура обмена**: 1С публикует изменения через **регистр сведений-очередь** (или планы обмена) + регламентное задание отправки — аналог outbox; получатель подтверждает, запись удаляется.

**Планы обмена**: механизм регистрации изменений объектов для узлов (кому что отправить), номера сообщений и подтверждения — основа РИБ и обменов между конфигурациями (Конвертация данных, EnterpriseData).

**HTTP-сервисы**: версионирование URL (`/api/v1/`), аутентификация (базовая через пользователя ИБ с ограниченными правами, лучше — токены через прокси), JSON через `ЗаписатьJSON`/`ПрочитатьJSON` и XDTO, обработка ошибок с кодами HTTP, логирование.

**Очереди**: 1С работает с брокерами через внешние компоненты или промежуточный сервис; частый подход — .NET-адаптер между 1С (HTTP) и Kafka/RabbitMQ.

**Производительность**: пакетная выгрузка, фоновые задания, не держать транзакцию во время HTTP-вызова.

**Интеграция с маркетплейсами/банками** — через промежуточный .NET-сервис: ретраи, лимиты API, идемпотентность, мониторинг — там, где это удобно делать.

# @onec-performance

## Глубже: расследование производительности 1С
**Методика**: собрать жалобы → измерить (APDEX по ключевым операциям) → технологический журнал за период проблемы → найти самые тяжёлые события (длительность × частота) → анализ (запросы, блокировки, клиент-серверные вызовы) → исправление → повторный замер.

**Технологический журнал** (`logcfg.xml`): события CALL/SCALL (вызовы), DBMSSQL/DBPOSTGRS (запросы с планами), TLOCK/TTIMEOUT/TDEADLOCK (управляемые блокировки), EXCP (исключения); анализ — скрипты, ЦУП, «Сервис для анализа ТЖ», агрегация по контекстам.

**Блокировки**: избыточные (блокировка всего регистра вместо измерений), длинные транзакции, эскалация блокировок в MS SQL, неправильный порядок захвата → дедлоки.

**СУБД**: статистика и индексы, настройки PostgreSQL для 1С (дистрибутив Postgres Pro/от 1С), обслуживание (реиндексация, VACUUM), достаточная память.

**Оборудование и кластер**: число рабочих процессов, сервер лицензирования, сеть между сервером 1С и СУБД (латентность!).
