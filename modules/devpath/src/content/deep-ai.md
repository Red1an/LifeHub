# @ai-math

## Глубже: математика, которая реально нужна
**Линейная алгебра**: матричное умножение как композиция преобразований; собственные векторы и SVD — основа PCA (снижение размерности) и низкоранговых приближений (LoRA дообучает модель через низкоранговые матрицы).

**Оптимизация**: стохастический градиентный спуск на мини-батчах, momentum, Adam; learning rate schedule (warmup + cosine decay); градиенты считают автоматически (**автодифференцирование** в PyTorch — строит граф вычислений и применяет chain rule).

**Вероятности и информация**: энтропия, **cross-entropy** как функция потерь классификации и языковых моделей, KL-дивергенция (RLHF, дистилляция), байесовское мышление.

**Статистика для инженера**: доверительные интервалы, A/B-тесты, p-value и его ограничения, распределения с тяжёлыми хвостами (латентность!).

**Как учить**: не «вся математика сначала», а по мере необходимости — «Mathematics for Machine Learning» (бесплатно) и 3Blue1Brown для интуиции.

# @ai-ml

## Глубже: ML-проект от начала до конца
**Формулировка**: бизнес-метрика → ML-задача → метрика модели → базовый уровень (простое правило или логистическая регрессия). Часто правило даёт 80% пользы.

**Данные**: сбор, разметка (качество разметки важнее объёма), разбиение по времени для задач прогнозирования (иначе утечка будущего), стратификация, балансировка классов.

**Признаки**: для табличных данных feature engineering решает больше, чем выбор модели; target encoding — осторожно с утечкой.

**Выбор модели**: градиентный бустинг (LightGBM/CatBoost) для таблиц; нейросети — для текста, изображений, звука; предобученные модели и эмбеддинги вместо обучения с нуля.

**Оценка**: кросс-валидация, метрики под задачу (PR-AUC для редких классов), калибровка вероятностей, анализ ошибок по сегментам, fairness.

**ML.NET**: обучение прямо в C#, AutoML (`mlnet` CLI, Model Builder), интеграция с ONNX и TensorFlow моделями; удобно для классификации, регрессии, рекомендаций внутри .NET-продукта.

# @ai-nn

## Глубже: обучение сетей на практике
**Инициализация** весов (Xavier, He) — без неё градиенты затухают или взрываются. **Нормализация** (BatchNorm, LayerNorm) стабилизирует обучение. **Residual-связи** (x + f(x)) позволяют обучать сети из сотен слоёв.

**Регуляризация**: dropout, weight decay, аугментация данных, ранняя остановка.

**Отладка обучения**: сначала переобучить на крошечной выборке (если не получается — ошибка в коде), следить за loss на train и validation, градиентными нормами, learning rate finder; mixed precision (fp16/bf16) для скорости и памяти.

**Transfer learning**: взять предобученную модель, заморозить большую часть, дообучить голову — стандартный путь для прикладных задач.

**Железо**: GPU (CUDA), память — главный ограничитель; batch size, gradient accumulation, gradient checkpointing.

**Karpathy «Zero to Hero»**: написать micrograd и GPT с нуля — лучший способ понять, как всё работает.

# @ai-arch

## Глубже: трансформеры изнутри
**Блок трансформера**: LayerNorm → multi-head self-attention → residual → LayerNorm → MLP (feed-forward) → residual. Современные модели: pre-norm, RMSNorm, SwiGLU, **RoPE** (позиционное кодирование поворотами), grouped-query attention.

**Декодер (GPT)**: causal mask — токен видит только предыдущие. Генерация — по одному токену; **KV-cache** хранит ключи и значения прошлых токенов, чтобы не пересчитывать — поэтому длинный контекст ест память.

**Цена attention** O(n²) по длине: FlashAttention (эффективное использование памяти GPU), sliding window, разреженные схемы.

**Mixture of Experts (MoE)**: много «экспертов»-MLP, для каждого токена активируются несколько — больше параметров при той же стоимости вычислений.

**Токенизация**: BPE, словарь 50–200 тысяч токенов; числа и редкие языки токенизируются неэффективно.

**Мультимодальность**: изображения режутся на патчи (ViT) и превращаются в токены — та же архитектура.

# @ai-llm

## Глубже: как выбирать и использовать LLM
**Выбор модели**: качество на **ваших** задачах (evals), латентность, стоимость за токены входа/выхода, контекстное окно, поддержка tool use и structured output, требования к данным (где обрабатываются), лицензия для открытых моделей. Часто — каскад: маленькая модель для простого, большая — для сложного.

**Рассуждающие модели** (reasoning, extended thinking): тратят токены на обдумывание — сильнее в математике, коде, планировании, но медленнее и дороже; для простого извлечения данных избыточны.

**Prompt caching**: провайдеры кэшируют длинный общий префикс (системный промпт, документы) — дешевле и быстрее повторные запросы; порядок: стабильное в начале, меняющееся в конце.

**Локальные модели**: Ollama/llama.cpp/vLLM; квантование GGUF 4–8 бит; требования к VRAM ≈ параметры × бит / 8 + KV-cache.

**Дообучение**: сначала промпт и RAG; fine-tuning (LoRA) — для стиля, формата, узкой задачи с множеством примеров; дистилляция большой модели в маленькую.

**Структурированный вывод**: JSON schema / tool calling с ограничением грамматики — модель физически не может выдать невалидный JSON.

# @ai-prompting

## Глубже: промпты для продакшена
**Структура** (работает с большинством моделей): роль и контекст → задача → входные данные в тегах (`<document>…</document>`) → правила и ограничения → формат вывода → примеры → «если данных недостаточно — скажи об этом».

**Few-shot**: 3–5 разнообразных примеров, включая пограничные; примеры сильнее инструкций влияют на формат.

**Декомпозиция**: цепочки промптов (извлечь → проверить → сформулировать), параллельные вызовы для независимых частей, модель-судья для проверки.

**Длинный контекст**: документы — в начало, вопрос — в конец; просить сначала выписать релевантные цитаты, потом отвечать.

**Надёжность**: temperature 0 для детерминированных задач, валидация вывода, повтор с сообщением об ошибке валидации, лимиты длины.

**Промпты как код**: в репозитории, с версиями, тестами (evals) и ревью; шаблоны с параметрами; A/B в проде.

**Безопасность**: пользовательский ввод — всегда в явных границах, никогда не смешивать с инструкциями; не класть секреты в промпт.

# @ai-embeddings

## Глубже: векторный поиск в продакшене
**Выбор модели эмбеддингов**: качество на ваших данных и языке (MTEB-рейтинг как ориентир), размерность (стоимость хранения), контекст (длина текста), мультиязычность. Для русского — мультиязычные модели (e5, bge-m3 и т.п.) или API провайдеров.

**Matryoshka-эмбеддинги** можно обрезать до меньшей размерности с умеренной потерей качества — экономия памяти.

**Индексы**: HNSW (параметры M и ef — баланс точности, памяти и скорости), IVF-PQ для огромных объёмов с квантованием; бинарная/скалярная квантизация векторов.

**Обновление**: при смене модели эмбеддингов нужно переиндексировать всё — храните исходный текст и версию модели.

# @ai-rag

## Глубже: продвинутый RAG
**Чанкинг**: по структуре документа (заголовки, абзацы), с перекрытием; **контекстные чанки** — к каждому фрагменту добавить краткое описание документа (contextual retrieval) — заметно улучшает поиск.

**Улучшение запроса**: переписывание вопроса с учётом истории диалога, HyDE (сгенерировать гипотетический ответ и искать по нему), разбиение сложного вопроса на подвопросы.

**Поиск**: гибридный (BM25 + векторы) + reranker (cross-encoder) — стандарт качества; фильтры по метаданным и правам.

**Генерация**: цитаты с идентификаторами чанков, инструкция отвечать только по контексту, «не знаю» при отсутствии данных.

**Agentic RAG**: модель сама решает, какие поиски сделать и когда достаточно информации (инструменты search/read), — лучше для сложных вопросов, дороже.

**GraphRAG** — извлечение сущностей и связей для вопросов «по всему корпусу».

**Оценка**: отдельно retrieval (recall@k) и generation (faithfulness, answer relevance); инструменты Ragas, собственные evals с LLM-судьёй.

# @ai-agents

## Глубже: как строить эффективных агентов
**Workflows vs agents** (Anthropic, «Building effective agents»): сначала простые **workflows** с заранее заданными шагами — prompt chaining, routing (классифицировать и направить), parallelization (секционирование, голосование), orchestrator-workers, evaluator-optimizer (генерация + критика в цикле). Полный агент (модель сама выбирает шаги) — только когда путь заранее неизвестен.

**Проектирование инструментов** (ACI — agent-computer interface): говорящие имена, подробные описания с примерами, простые форматы, понятные ошибки с подсказкой, как исправить; меньше инструментов с чёткими границами лучше, чем много похожих.

**Контекст агента**: история действий растёт — сжатие, заметки/память в файлах, субагенты для изолированных подзадач.

**Надёжность**: лимиты шагов и стоимости, таймауты, детерминированные проверки результата, человек в цикле для необратимого, журнал всех вызовов.

**Протоколы**: MCP для инструментов и данных; A2A (Agent2Agent) для взаимодействия агентов разных систем.

**Оценка агентов**: задачи с проверяемым конечным состоянием, успех по траекториям, стоимость и число шагов.

# @ai-evals

## Глубже: как строить evals
**Начните с анализа ошибок**: соберите 50–100 реальных трасс, прочитайте их, выпишите типы ошибок (открытое кодирование), сгруппируйте — это и есть ваши метрики. Готовые общие метрики («полезность 1–5») малополезны.

**Типы проверок**: детерминированные (JSON валиден, есть ссылка, нет запрещённых слов, правильный вызов инструмента), сравнение с эталоном, LLM-судья с **бинарными** критериями и примерами, человеческая разметка для калибровки судьи (согласие с человеком — precision/recall судьи).

**Наборы**: golden set (регрессия), adversarial (попытки сломать), срезы по типам пользователей и задач; синтетические примеры генерировать осторожно и проверять.

**В процессе**: evals в CI на изменения промптов/моделей, сравнение с базовой версией, онлайн-мониторинг в проде (выборка трасс, пользовательский фидбек), новые ошибки → новые примеры.

**Инструменты**: собственные скрипты часто лучше фреймворков; Promptfoo, Braintrust, LangSmith, Microsoft.Extensions.AI.Evaluation.

## Глубже: жизненный цикл модели в проде
**Уровни зрелости MLOps** (Google): 0 — ручное обучение и деплой; 1 — автоматический конвейер обучения (continuous training); 2 — CI/CD самого конвейера.

**Feature store** — единые признаки для обучения и инференса, чтобы избежать training-serving skew (признаки считаются по-разному в обучении и в проде).

**Управление**: реестр моделей с метаданными (данные, код, метрики), воспроизводимость, одобрение перед продом, откат; model cards (назначение, ограничения, риски).
