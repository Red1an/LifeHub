# @cs-complexity

## Глубже: за пределами O-нотации
**Константы важны**: O(n) с плохой локальностью памяти может проиграть O(n log n) с хорошей; на маленьких n простой алгоритм выигрывает (поэтому introsort переключается на вставки для маленьких массивов).

**Амортизированный анализ** — метод потенциалов и банковский метод: «копим» стоимость дешёвых операций, чтобы оплатить дорогие. **Ожидаемая сложность** (хэш-таблица, quicksort) отличается от худшего случая — злоумышленник может спровоцировать худший (hash flooding).

**Нижние границы**: сортировка сравнениями не быстрее Ω(n log n); подсчётом/поразрядно — O(n + k) для ограниченных ключей.

**Master theorem** для рекуррент «разделяй и властвуй»: T(n) = aT(n/b) + f(n) — сразу даёт сложность merge sort (n log n), бинарного поиска (log n), Карацубы.

**Практические классы**: P, NP, NP-полные задачи (коммивояжёр, рюкзак в общем виде) — если задача NP-полная, ищите эвристики, приближённые алгоритмы или ограничения размера, а не «точный быстрый» алгоритм.

Q: Чем ожидаемая сложность отличается от сложности в худшем случае и почему это важно?
A: Ожидаемая — среднее по случайности алгоритма или входа (хэш-таблица O(1), quicksort O(n log n)); худший случай может быть O(n) и O(n²). Злоумышленник способен подобрать вход под худший случай (hash flooding), поэтому используют рандомизацию хэшей и гибридные алгоритмы.

# @cs-arrays

## Глубже: продвинутые техники на массивах
**Префиксные суммы 2D**: сумма любого прямоугольника матрицы за O(1). **Разностный массив**: прибавить x на отрезке за O(1), итог — префиксной суммой.

**Монотонная очередь (deque)**: максимум в скользящем окне за O(n) — храним индексы кандидатов в убывающем порядке значений.

**Хэширование с префиксами**: «число подмассивов с суммой k» — словарь частот префиксных сумм; «самый длинный подмассив с равным числом 0 и 1» — префикс с заменой 0 на −1.

**Алгоритм Кадане** — максимальная сумма подмассива за O(n).

**Сортировка + два указателя** — 3Sum за O(n²); **голландский флаг** — разбиение на три группы за один проход.

**Строки**: KMP/Z-функция для поиска подстроки за O(n + m), rolling hash (Рабин–Карп), trie для множества слов.

В .NET: `Span<T>` для срезов без копий, `ArrayPool` для временных буферов, `Array.Sort` с `Comparison`, `CollectionsMarshal.AsSpan(list)`.

# @cs-structures

## Глубже: структуры для сложных задач
**Дерево отрезков** — сумма/минимум на отрезке и изменение элемента за O(log n); с отложенными операциями — изменение на отрезке. **Дерево Фенвика** — проще и компактнее для префиксных сумм.

**Сбалансированные деревья**: красно-чёрное (SortedSet, SortedDictionary), AVL; skip list (Redis sorted set) — вероятностная альтернатива.

**Хэш-структуры**: bloom filter — «точно нет / возможно да» с малой памятью (кэши, LSM); HyperLogLog — приблизительное число уникальных; count-min sketch — частоты в потоке.

**Кучи**: двоичная (PriorityQueue); d-арная для частых decrease-key; куча в .NET не поддерживает изменение приоритета — добавляйте дубликат и игнорируйте устаревшие при извлечении (ленивое удаление).

**LRU/LFU**: LRU — словарь + двусвязный список; LFU — частоты + списки по частоте за O(1).

**Неизменяемые структуры**: persistent-деревья с разделением узлов (ImmutableList) — дешёвые снимки.

# @cs-trees

## Глубже: алгоритмы на графах
**Кратчайшие пути**: BFS (без весов), 0-1 BFS (веса 0/1, deque), Дейкстра (неотрицательные), Беллман–Форд (отрицательные, обнаружение отрицательных циклов), Флойд–Уоршелл (все пары, O(V³)), A* (эвристика для карт).

**Остовные деревья**: Краскал (сортировка рёбер + union-find), Прим (куча).

**Компоненты**: сильно связные компоненты (Тарьян, Косарайю) — циклы зависимостей; мосты и точки сочленения — уязвимые места сети.

**Топологическая сортировка** Каном — заодно обнаруживает цикл (не все вершины обработаны).

**Union-Find** с сжатием путей и объединением по рангу — почти O(1) (обратная функция Аккермана).

**Деревья**: LCA (наименьший общий предок) через двоичные подъёмы; обходы без рекурсии (стек) для глубоких деревьев — рекурсия на 10⁵ уровнях переполнит стек.

**Графы в жизни**: зависимости сборки, маршрутизация, рекомендации, поиск циклов в заказах/транзакциях.

# @cs-dp

## Глубже: DP на собеседовании и в жизни
**Классы задач**: линейная (лестница, грабитель домов), на подпоследовательностях (LIS, LCS), на отрезках (перемножение матриц, палиндромы — `dp[i][j]` по длине отрезка), рюкзак (0/1, неограниченный, с восстановлением ответа), на деревьях (DFS снизу вверх), на масках подмножеств (коммивояжёр для n ≤ 20), на цифрах числа.

**Восстановление ответа**: храните, откуда пришёл оптимум (или пересчитывайте назад по таблице).

**Оптимизация памяти**: если строка зависит только от предыдущей — два массива или один с обратным обходом (0/1 рюкзак).

**LIS за O(n log n)**: массив «хвостов» + бинарный поиск.

**Где DP в реальной разработке**: diff текстов (LCS/Майерс), расстояние редактирования для опечаток и нечёткого поиска, выравнивание, планирование ресурсов, биллинг с тарифами.

**Подход на интервью**: рекурсия с перебором → мемоизация → табуляция → оптимизация памяти, объясняя каждый шаг.

# @cs-search

## Глубже: бинарный поиск и жадность глубже
**Инвариант бинарного поиска**: выберите полуинтервал `[lo, hi)` и условие «предикат ложен слева, истинен справа» — ищем первое истинное. Так пишутся lower/upper bound без ошибок на единицу.

**Поиск по вещественному ответу**: фиксированное число итераций (100) вместо сравнения с eps.

**Тернарный поиск** — экстремум унимодальной функции; **экспоненциальный поиск** — когда граница неизвестна (удваивать hi).

**Жадные алгоритмы — как доказывать**: «аргумент обмена» (любое оптимальное решение можно перестроить в жадное, не ухудшив) или «жадный всегда впереди». Контрпример на маленьком примере — быстрый способ опровергнуть жадность.

**Классика жадности**: Хаффман (сжатие), задачи расписания (минимизация задержек — по дедлайну), Краскал/Прим, заправки на маршруте, задачи о покрытии интервалами.

**В .NET**: `Array.BinarySearch` возвращает `~index` при отсутствии — побитовое отрицание даёт место вставки; `List<T>.BinarySearch`, `CollectionsMarshal`.

---recall
Q: Как писать бинарный поиск без ошибок на единицу?
A: Сформулировать монотонный предикат (ложь…ложь, истина…истина), выбрать полуинтервал [lo, hi), на каждом шаге mid = lo + (hi − lo) / 2; если предикат истинен — hi = mid, иначе lo = mid + 1; ответ — lo (первое истинное).

# @cs-os

## Глубже: что ОС делает для вашего сервиса
**Системные вызовы** стоят сотни наносекунд (переход в ядро); буферизация I/O уменьшает их число. **Контекстные переключения** ~ микросекунды + потеря кэшей.

**Виртуальная память**: TLB-промахи на больших случайных обращениях; **huge pages** уменьшают их (БД). `mmap` — отображение файла в память (Memory-mapped files в .NET).

**Планировщик Linux** (CFS → EEVDF): приоритеты nice, cgroups CPU quota — отсюда троттлинг в контейнерах, `cpu.shares`/`cpu.max`.

**I/O**: page cache, `fsync` для гарантии записи на диск (БД делают это аккуратно), direct I/O, **io_uring** — асинхронный I/O через кольцевые буферы без системного вызова на каждую операцию (используется в новых версиях рантаймов и БД).

**Сеть в ядре**: очереди сокетов (backlog), `SO_REUSEPORT`, epoll edge-triggered.

**Процессы в .NET**: `Environment.ProcessorCount` учитывает лимит контейнера; `GCHeapAffinitize` и привязка потоков — для специальных случаев.

# @cs-hardware

## Глубже: писать код, дружелюбный к железу
**Data-oriented design**: массивы структур (AoS) против структур массивов (SoA) — если цикл читает одно поле у миллиона объектов, SoA загружает только нужные данные в кэш. В .NET: `struct` в массивах вместо классов, `Span<T>`, избегать указателей-переходов.

**Предвыборка**: процессор угадывает последовательный доступ; случайный (связные структуры, хэш-таблицы большого размера) — промахи.

**Ветвления**: branchless-код (`Math.Max`, условное присваивание) для непредсказуемых данных; сортировка данных перед обработкой делает ветки предсказуемыми.

**SIMD в .NET**: `Vector128/256/512<T>`, `Vector.IsHardwareAccelerated`, аппаратные интринсики (`Avx2`, `AdvSimd`) с запасной веткой; `TensorPrimitives` — готовые векторизованные операции над Span.

**Многопоточность и кэш**: false sharing, `[StructLayout(Size = 64)]` или паддинг; NUMA на больших серверах.

**Числа, которые нужно помнить** (Джефф Дин): L1 0.5 нс, промах предсказания 5 нс, L2 7 нс, мьютекс 25 нс, RAM 100 нс, 1 КБ по сети 1 Гбит — 10 мкс, SSD случайное чтение 150 мкс, поездка по ДЦ 0.5 мс, диск seek 10 мс.

# @cs-patterns

## Глубже: как готовиться системно
**План на 6–8 недель**: неделя на 1–2 паттерна (по 5–8 задач: лёгкие → средние), в конце недели — смешанные задачи на время. После — 2–3 пробных интервью в неделю.

**Разбор решённого**: запишите паттерн, ключевую идею одной фразой, сложность, типичную ошибку. Через 3 и 10 дней решайте снова без подсказки — интервальное повторение для алгоритмов.

**Коммуникация**: рассуждайте вслух, начинайте с примера, уточняйте ограничения, предлагайте наивное решение, признавайте застревание и просите подсказку — это нормально.

**Код**: чистые имена, вспомогательные функции, проверка крайних случаев (пусто, один элемент, дубликаты, отрицательные, переполнение), тест «в голове» на примере.

**Senior-интервью** часто смещаются: меньше головоломок, больше реалистичных задач (итераторы, кэш, rate limiter, парсер, конкурентный код) и обсуждения масштабирования решения.

**C# на интервью**: `PriorityQueue`, `SortedSet` (как сбалансированное дерево с Min/Max), `Dictionary.TryGetValue`, `Array.Fill`, `stackalloc` не нужен — важна ясность.
