# @ai-math

## Векторы и матрицы
Всё в ML — числа в векторах и матрицах. Картинка 28×28 — вектор из 784 чисел; слово — вектор эмбеддинга; слой нейросети — умножение вектора на матрицу весов плюс смещение: **y = Wx + b**.

- **Скалярное произведение** a·b — мера «похожести направлений»; на нём построены attention и поиск по эмбеддингам.
- **Норма** — длина вектора; **косинусная близость** = a·b / (|a||b|).
- Умножение матриц — основная операция, которую GPU выполняют массово параллельно.

## Производные и градиент
**Производная** — скорость изменения функции. **Градиент** — вектор частных производных: направление наискорейшего роста функции. Обучение модели — поиск весов, минимизирующих **функцию потерь**: шагаем против градиента (**градиентный спуск**):
```
w ← w − η · ∂L/∂w       (η — learning rate)
```
**Chain rule** (производная сложной функции) позволяет вычислить градиенты по всем слоям сети — это и есть backpropagation.

## Вероятности
- Распределения: нормальное, Бернулли, категориальное.
- Условная вероятность и формула Байеса.
- **Softmax** превращает набор чисел в вероятности (сумма = 1) — выход классификаторов и языковых моделей.

## Функции потерь
- **MSE** (среднеквадратичная ошибка) — регрессия.
- **Cross-entropy** — классификация и языковые модели: штрафует уверенные неправильные ответы.

# @ai-ml

## Виды обучения
- **С учителем** — есть правильные ответы: классификация (спам/не спам), регрессия (цена квартиры).
- **Без учителя** — ищем структуру: кластеризация, снижение размерности, поиск аномалий.
- **С подкреплением** — агент учится через награды (игры, RLHF для LLM).

## Классические модели
- **Линейная/логистическая регрессия** — просто, интерпретируемо, хорошая база.
- **Деревья решений** — правила if-else, легко переобучаются.
- **Случайный лес** — много деревьев на разных подвыборках, голосование.
- **Градиентный бустинг** (XGBoost, LightGBM, CatBoost) — деревья учатся исправлять ошибки предыдущих. **Король табличных данных**: для таблиц часто лучше нейросетей.

## Переобучение
Модель запомнила обучающие данные, но плохо работает на новых. Признак — низкая ошибка на train и высокая на validation. Лечение: больше данных, регуляризация (L1/L2, dropout), упрощение модели, ранняя остановка, кросс-валидация.

Данные делят на **train / validation / test**. Test трогают один раз в конце. Опасность — **утечка данных** (data leakage): признак, который содержит информацию о ответе или о будущем.

## Метрики
- **Accuracy** — доля верных; обманчива при несбалансированных классах (99% «не мошенничество» — accuracy 99% у модели, которая всегда говорит «нет»).
- **Precision** — из предсказанных положительных сколько верных.
- **Recall** — из всех реальных положительных сколько нашли.
- **F1** — гармоническое среднее precision и recall.
- **ROC-AUC** — качество ранжирования независимо от порога.

В .NET — **ML.NET**: обучение и инференс классических моделей на C#, AutoML (Model Builder).

Q: Чем precision отличается от recall? Когда что важнее?
A: Precision — доля верных среди предсказанных положительными; recall — доля найденных среди всех положительных. Recall важнее, когда пропуск дорог (диагностика болезни, мошенничество), precision — когда дороги ложные срабатывания (спам-фильтр, блокировка платежей).

# @ai-nn

## Нейрон и слои
Нейрон: взвешенная сумма входов + смещение → **функция активации**. Слой — много нейронов; сеть — слои подряд. Без нелинейных активаций вся сеть схлопнулась бы в одно линейное преобразование.

Активации: **ReLU** (max(0, x)) — стандарт для скрытых слоёв; sigmoid/softmax — на выходе для вероятностей; GELU — в трансформерах.

## Обучение
1. **Прямой проход**: вход → предсказание.
2. **Потери**: сравниваем с правильным ответом.
3. **Backpropagation**: по правилу цепочки вычисляем градиент потерь по каждому весу, от выхода к входу.
4. **Оптимизатор** обновляет веса: SGD, **Adam** (адаптивный шаг для каждого параметра, стандарт по умолчанию).

Данные идут **батчами** (например, по 64 примера); **эпоха** — один проход по всему датасету. **Learning rate** — главный гиперпараметр: слишком большой — обучение расходится, слишком малый — ползёт.

## Проблемы и приёмы
- Затухающие/взрывающиеся градиенты → нормализация (BatchNorm, LayerNorm), residual-связи.
- Переобучение → dropout, аугментация данных, weight decay.
- Нужно много данных и GPU; готовые **предобученные модели** + дообучение (transfer learning) экономят и то и другое.

## PyTorch в двух словах
```python
model = torch.nn.Sequential(torch.nn.Linear(784, 128), torch.nn.ReLU(), torch.nn.Linear(128, 10))
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
for x, y in loader:
    loss = torch.nn.functional.cross_entropy(model(x), y)
    opt.zero_grad(); loss.backward(); opt.step()
```

A: Алгоритм вычисления градиента функции потерь по всем весам сети: проходит от выхода к входу, применяя правило цепочки и переиспользуя промежуточные результаты. Полученные градиенты использует оптимизатор для обновления весов.

# @ai-arch

## Свёрточные сети (CNN)
Для изображений: небольшие фильтры скользят по картинке и находят локальные признаки (края → текстуры → части объектов → объекты). Общие веса фильтров → мало параметров, устойчивость к сдвигу. Применение: классификация, детекция (YOLO), сегментация.

## Рекуррентные сети (RNN, LSTM)
Обрабатывают последовательность по шагу, передавая скрытое состояние. Проблемы: последовательная обработка (плохо параллелится) и **забывание** далёкого контекста (LSTM/GRU смягчают). Сегодня почти вытеснены трансформерами.

## Attention и трансформер
**Self-attention**: каждый токен формирует query (что ищу), key (что содержу), value (что отдаю). Вес внимания токена i к токену j = softmax(qᵢ·kⱼ / √d). Выход — взвешенная сумма value. Так каждый токен «смотрит» на все остальные сразу — дальние связи, полная параллельность обучения.

Трансформер = attention (много «голов») + полносвязные слои + residual-связи + нормализация, повторённые десятки раз. **Позиционное кодирование** сообщает о порядке токенов. Варианты: encoder (BERT — понимание), decoder (GPT — генерация), encoder-decoder (T5, перевод). Цена attention — O(n²) от длины контекста.

## Токенизация
Модель работает не со словами, а с **токенами** — частями слов (BPE, SentencePiece). Английский текст ≈ 4 символа на токен, русский — меньше символов на токен, поэтому дороже. Токены определяют стоимость API и длину контекста; странности токенизации объясняют, почему LLM плохо считает буквы в словах.

Q: Что такое query, key и value в attention?
A: Три линейные проекции представления токена. Query — что токен ищет, key — по чему его находят другие, value — информация, которую он передаёт. Сходство query и key (скалярное произведение + softmax) даёт веса, с которыми суммируются value.

# @ai-llm

## Как появляется LLM
1. **Предобучение**: предсказание следующего токена на триллионах токенов текста и кода. Модель усваивает язык, факты, паттерны рассуждений.
2. **Instruction tuning (SFT)**: дообучение на парах «инструкция — хороший ответ».
3. **Выравнивание** (RLHF, RLAIF, DPO): модель учится давать полезные и безопасные ответы по предпочтениям людей или других моделей.

## Параметры генерации
Модель выдаёт распределение вероятностей следующего токена:
- **temperature** — «острота» распределения: 0 — почти детерминировано, выше — разнообразнее;
- **top-p / top-k** — выбирать только из самых вероятных вариантов;
- **max tokens** — лимит ответа.
**Контекстное окно** — сколько токенов модель видит сразу (промпт + история + ответ).

## Ограничения
- **Галлюцинации** — модель генерирует правдоподобный, но ложный текст: она оптимизирована на правдоподобие, а не на истину. Лечение — давать факты в контексте (RAG), просить ссылки, проверять.
- Отсечка знаний по дате обучения.
- Слабость в точных вычислениях — отдавать инструментам (tool use).
- Стоимость и латентность растут с числом токенов.

## Открытые модели
Llama, Mistral, Qwen, DeepSeek, Gemma — можно запускать локально (**Ollama**, LM Studio, vLLM). **Квантование** (4–8 бит вместо 16) уменьшает память в разы при небольшой потере качества. **Fine-tuning** (LoRA) — дообучить под свою задачу; чаще достаточно хорошего промпта и RAG.

Q: Из каких этапов состоит создание современной LLM?
A: Предобучение на огромном корпусе (предсказание следующего токена), затем supervised fine-tuning на инструкциях и выравнивание по предпочтениям (RLHF/DPO), чтобы модель была полезной, честной и безопасной.

# @ai-prompting

## Основы хорошего промпта
- **Роль и контекст**: кто модель, для кого ответ, какая цель.
- **Чёткая задача** и критерии успеха.
- **Формат вывода**: структура, длина, JSON-схема.
- **Примеры** (few-shot) — показать 2–3 образца лучше, чем долго описывать.
- **Ограничения**: что делать, если данных нет («скажи, что не знаешь»).
- Разделять инструкции и данные (XML-теги, тройные кавычки).

## Рассуждения
Для сложных задач попросите модель **подумать по шагам** перед ответом (chain-of-thought) — или используйте модели с встроенным «размышлением». Разбивайте большие задачи на цепочку промптов (сначала извлечь факты, потом проанализировать, потом сформулировать).

## Структурированный вывод
Для кода, который потребляет ответ, — **JSON по схеме** (structured outputs / tool calling), валидация результата, повтор при ошибке. Не парсите свободный текст регулярками.

## Оценка и безопасность
- Промпт — это код: версионируйте его и проверяйте набором **evals** (примеры с ожидаемыми ответами), а не «на глаз».
- **Prompt injection**: пользовательские данные или документы содержат «игнорируй инструкции и…». Защита: не давать модели лишних прав, отделять данные от инструкций, проверять действия, подтверждение человеком для опасных операций.

# @ai-embeddings

## Что такое эмбеддинг
Модель эмбеддингов превращает текст (или картинку) в вектор из сотен-тысяч чисел так, что **близкие по смыслу** тексты дают близкие векторы. «Как вернуть деньги?» и «Процедура возврата средств» окажутся рядом, хотя слов общих нет.

Близость — **косинусная** (угол между векторами) или скалярное произведение для нормализованных векторов.

## Векторный поиск
Храним эмбеддинги документов, для запроса считаем эмбеддинг и ищем k ближайших. Точный перебор — O(n); на миллионах векторов используют **приближённый поиск (ANN)**:
- **HNSW** — многоуровневый граф «соседей», быстрый и точный, стандарт де-факто;
- IVF — кластеры с поиском в ближайших.

Хранилища: **pgvector** (расширение PostgreSQL — часто достаточно), Qdrant, Weaviate, Milvus, Elasticsearch/OpenSearch, Azure AI Search, Redis.

## Гибридный поиск
Векторный поиск хорош по смыслу, но плох по точным совпадениям (артикулы, имена, коды ошибок). **Гибрид** = BM25 (ключевые слова) + векторы, объединение результатов (Reciprocal Rank Fusion) — обычно лучше каждого по отдельности.

```sql
CREATE EXTENSION vector;
CREATE TABLE chunks (id bigserial PRIMARY KEY, text text, embedding vector(1536));
CREATE INDEX ON chunks USING hnsw (embedding vector_cosine_ops);
SELECT text FROM chunks ORDER BY embedding <=> @query LIMIT 5;
```

# @ai-rag

## Идея RAG
**Retrieval-Augmented Generation**: перед генерацией найти релевантные фрагменты ваших документов и положить их в промпт. Модель отвечает **по данным**, а не по памяти: меньше галлюцинаций, актуальные и приватные знания без дообучения, можно давать ссылки на источники.

## Конвейер
**Индексация**: загрузка документов → очистка → **чанкинг** (фрагменты по 200–800 токенов, по структуре документа, с перекрытием) → эмбеддинги → векторное хранилище (с метаданными: источник, дата, права доступа).

**Запрос**: (перефразировать запрос) → поиск top-k (гибридный) → **reranking** (кросс-энкодер точнее переоценивает кандидатов) → промпт: «ответь только по контексту, укажи источники, если ответа нет — так и скажи» → генерация.

## Где ломается
- неудачный чанкинг (ответ разорван между кусками, таблицы порезаны);
- поиск не нашёл нужное (нужен гибрид, переформулировка, metadata-фильтры);
- в контексте слишком много мусора — модель отвлекается;
- устаревшие документы, нет прав доступа на уровне фрагментов;
- вопрос требует агрегации по всем документам («сколько всего…») — RAG тут слаб.

## Оценка
Отдельно оцениваем **поиск** (нашёлся ли нужный фрагмент: recall@k) и **генерацию** (faithfulness — ответ опирается на контекст; relevance — отвечает на вопрос). Набор тестовых вопросов с эталонами — обязателен.

- [ ] Для шифрования
> Первичный поиск быстрый, но грубый.

? Расставь этапы RAG при ответе на вопрос

2. Найти кандидатов (векторный/гибридный поиск)
3. Переранжировать и отобрать лучшие фрагменты
4. Сформировать промпт с контекстом и сгенерировать ответ со ссылками
> Индексация документов происходит заранее.

A: Раздельно: поиск (попал ли нужный фрагмент в top-k — recall@k, MRR) и генерацию (faithfulness — опора на контекст без выдумок, relevance — ответ на вопрос, корректность относительно эталона). Набор тестовых вопросов, прогон после каждого изменения.

# @ai-agents

## От чата к агенту
**Tool use / function calling**: модели описывают доступные функции (имя, описание, JSON-схема параметров); модель решает вызвать функцию и возвращает аргументы; ваш код выполняет вызов и отдаёт результат модели; цикл повторяется до финального ответа. Это и есть агент: **LLM в цикле с инструментами**.

```
пользователь → модель → «вызови search_orders(customer=42)» → код выполняет → результат → модель → ответ
```

## MCP
**Model Context Protocol** — открытый стандарт подключения инструментов и данных к ИИ-приложениям: один MCP-сервер (доступ к БД, GitHub, файлам, вашему API) работает с разными клиентами (Claude, IDE, свои приложения). Есть SDK для C#.

## Проектирование агентов
- Начинайте с простого: чёткий промпт + несколько хорошо описанных инструментов.
- Инструменты — как хорошее API: понятные имена, описания, валидация, информативные ошибки.
- Ограничения: максимум шагов, таймауты, бюджет токенов.
- **Память**: история диалога, заметки агента, поиск по прошлому.
- Оркестрация: один агент с инструментами; «планировщик + исполнители»; несколько специализированных агентов — только когда это реально нужно.

## Безопасность
Агент выполняет действия — значит, ошибка или prompt injection имеют последствия. Минимальные права, песочницы, подтверждение человеком опасных операций (платёж, удаление, отправка), журнал действий, не доверять данным из внешних источников как инструкциям.

# @ai-dotnet

## Microsoft.Extensions.AI
Единые абстракции для работы с моделями в .NET:
- `IChatClient` — чат с любой моделью (OpenAI, Azure OpenAI, Ollama, Anthropic через адаптеры);
- `IEmbeddingGenerator<string, Embedding<float>>` — эмбеддинги;
- middleware-конвейер: логирование, кэш, телеметрия, **автоматический вызов функций**.
```csharp
IChatClient client = new OllamaChatClient(new Uri("http://localhost:11434"), "llama3.1")
    .AsBuilder().UseFunctionInvocation().UseOpenTelemetry().Build();

var tools = new ChatOptions { Tools = [AIFunctionFactory.Create((string city) => GetWeather(city), "get_weather")] };
var reply = await client.GetResponseAsync("Какая погода в Казани?", tools);
```

## Semantic Kernel
Фреймворк Microsoft поверх этих абстракций: плагины (функции для модели), агенты, оркестрация, память и векторные хранилища, шаблоны промптов. Удобен для сложных сценариев; для простых хватает Microsoft.Extensions.AI.

## Локально
- **ONNX Runtime** — инференс экспортированных моделей (классификация, эмбеддинги, небольшие LLM) прямо в процессе .NET, на CPU или GPU.
- **Ollama** — локальный сервер открытых LLM с HTTP API.
- ML.NET — классическое ML.

## Инженерия
- Стоимость = токены: кэшируйте ответы и эмбеддинги, используйте маленькие модели для простых задач.
- Латентность: стриминг ответа (`GetStreamingResponseAsync`) + SSE до клиента.
- Надёжность: таймауты, ретраи с учётом rate limit провайдера, fallback на другую модель.
- Наблюдаемость: токены, стоимость, латентность, ошибки — в метрики (OpenTelemetry GenAI conventions).

# @ai-evals

## Зачем evals
Изменили промпт, модель или чанкинг — стало лучше или хуже? «Попробовал пару вопросов» не работает: улучшение в одном месте ломает другое. **Evals** — автоматические тесты качества ИИ-функции.

## Наборы данных
- **Золотой набор**: 50–500 реальных входов с эталонными ответами или критериями.
- Покрытие: типичные случаи, крайние, «ответа нет», попытки злоупотребления.
- Пополнение из прода: каждый найденный плохой ответ → новый тестовый пример.

## Способы оценки
- **Точные проверки** — когда ответ формальный: JSON валиден, поля совпадают, класс правильный.
- **Метрики близости** к эталону.
- **LLM-as-a-judge** — другая модель оценивает ответ по рубрике («опирается ли на контекст», «вежлив ли»). Дёшево и масштабируемо, но судья тоже ошибается: калибруйте его на примерах с человеческой разметкой, используйте бинарные критерии, а не шкалу 1–10.
- **Человеческая оценка** — эталон, но дорого; для калибровки и спорных случаев.

## В процессе разработки
Evals запускаются в CI при изменении промптов и конфигурации, результаты сравниваются с прошлым прогоном. В проде — онлайн-метрики: отзывы пользователей, доля эскалаций, A/B-тесты. При смене модели (новая версия у провайдера) — обязательный прогон: регрессии случаются.

# @ai-mlops

## Модель — это не только код
ML-система = код + **данные** + **модель** + конфигурация. Всё должно быть воспроизводимо: на каких данных, каким кодом и с какими параметрами обучена модель в проде.

## Жизненный цикл
1. Подготовка и **версионирование данных** (DVC, lakeFS, снапшоты).
2. Эксперименты с трекингом метрик и параметров (**MLflow**, Weights & Biases).
3. **Реестр моделей**: версии, стадии (staging/production), происхождение.
4. **Сервинг**: REST/gRPC-сервис, батч-инференс, в процессе приложения (ONNX).
5. **Мониторинг**: качество, латентность, стоимость, **дрейф**.
6. Переобучение по расписанию или триггеру.

## Дрейф
- **Data drift** — изменилось распределение входных данных (новая аудитория, сезон).
- **Concept drift** — изменилась связь входа и ответа (мошенники сменили тактику).
Модель деградирует молча, без ошибок в логах — нужны метрики распределений и качества на отложенной разметке.

## Выкатка
Модели выкатывают как код: shadow-режим (новая модель считает, но не влияет), canary, **A/B-тест** по бизнес-метрике, быстрый откат на предыдущую версию из реестра.

Q: Чем data drift отличается от concept drift?
A: Data drift — меняется распределение входных признаков (другие пользователи, сезонность). Concept drift — меняется сама зависимость между входами и правильным ответом (новые схемы мошенничества). Оба снижают качество модели без явных ошибок.
