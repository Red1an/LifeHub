# Расписание

Ставит события в Google Календарь по просьбам текстом, по фото (расписание пар, афиша, скриншот переписки)
и по данным других модулей (Форма, DevPath, Привычки). Перед записью всегда показывает черновик.

## Заметки по модулю

- **Google** — через `google.calendar()` SDK (разрешение `google:calendar`). Аккаунт подключается в настройках хаба,
  токен модулю не виден. Обёртки над API — `src/lib/gcal.ts`. После любых изменений вызывать `eventsChanged()` —
  страницы перечитают события.
- **Свои события** помечаются `extendedProperties.private.lifehub = "planner"` (+ `category`, `source`). Нейронка может
  менять и удалять **только** их (`normalize` в `lib/planner.ts` отбрасывает остальные). Чужие события — только
  занятое время.
- **Целевой календарь** — `prefs.calendarId` (по умолчанию предлагается создать отдельный «LifeHub»).
  `prefs.readCalendars` пусто → показываем календари, видимые в Google (`selected`).
- **Нейронка** (`lib/planner.ts`): `ai.json` с картинками (`images` — id файлов модуля). В запрос идут: текущая дата и
  ближайшие дни с днями недели (иначе путает «в пятницу»), настройки дня, занятость на `prefs.horizon` дней, события
  LifeHub с id, тексты источников. Ответ — `{summary, questions, events[]}` → `Draft[]`. Повторы — одно событие с
  `recurrence` (RRULE собирается в `gcal.ts`). Уточнение черновика — тот же запрос + текущий черновик + просьба.
- **Напоминания**: у черновика `kind: "event" | "reminder"` и `reminders: number[]` (минут до начала; у событий на весь
  день — от полуночи их дня). Нет поля — `remindersOf()` берёт настройки (`prefs.reminder`, `allDayReminder`), старое
  поле `reminder` тоже читается. Напоминание — короткое событие с `transparency: "transparent"` (не занимает время) и
  `extendedProperties.private.kind = "reminder"`; без времени ставится на `prefs.reminderTime`, а не на весь день.
- **Диктовка**: Chrome на Android присылает фразы накопительно — `mergeResults()` в `components/input.tsx` склеивает их
  без повторов; текст поля каждый раз собирается заново из всех результатов (база — текст на момент старта).
- **Дедлайны** (`lib/tasks.ts`, `lib/slots.ts`, `pages/Tasks.tsx`): задача = срок + объём + длина блока. Нейронка только
  описывает задачу (`tasks` в ответе), блоки раскладывает `planTask` кодом: по свободным окнам (`freeSlots`, с буфером),
  равномерно до дня перед сроком, не больше `prefs.taskPerDay` в день; сначала только целые блоки, мелкие куски — лишь
  если иначе не успеть; не влезло — `unplaced`. События блоков помечены `private.task` + `role` (block/deadline). Задача
  хранится в коллекции `tasks` (id = id задачи) с id событий блоков; отметки «сделал» — `markBlock`.
- **«Не успел»** — `components/move.tsx`: ближайшие окна той же длины (для блока задачи — до дедлайна), перенос PATCH.
- **Статистика** (`pages/Stats.tsx`) и **сводка дня** (`components/summary.tsx`) считаются по событиям недели без нейронки.
- **ГУАП** (`lib/guap.ts`, `pages/Guap.tsx`): guap.ru/rasp отдаёт HTML без входа (`?gr=<id>`, id группы — из `#selGroup`).
  ▲ `.week1` — верхняя (нечётная), ▼ `.week2` — нижняя (чётная), чётность текущей недели — в `.alert`. Занятия → повторы
  WEEKLY (interval 2 для ▲/▼) до `prefs.guapUntil`, `source: "guap"`; при повторном импорте старые серии удаляются
  (`listOurBySource`). Тот же разбор понимает скопированный текст страницы. В JS-регулярках `` не работает с кириллицей.
- **Модель** — `prefs.model` (по умолчанию sonnet): SDK принимает и конкретные `haiku | sonnet | opus`.
- **Черновик** — `useStore("plan")` (переживает перезагрузку и виден с телефона). Применение — по одному событию;
  неудавшиеся остаются в черновике. Итог — коллекция `history`.
- **Дела из «Заметок»** (`lib/notes.ts`, `components/notetodos.tsx`, разрешение `read:notes`): дела живут в «Заметках»,
  здесь — только «когда». Блок «Дела из заметок» на странице «Дела» (`/tasks`): «Найти время» ставит событие сразу в
  выбранное окно (`nextSlots`), «До срока» — задача с блоками через черновик. `/tasks?note=<id>` открывает окна для дела,
  `/ask?note=<id>&text=…` — запрос из заметки: всё созданное получает `Draft.noteId` → `private.note`, у задачи `noteId`.
  Писать в чужие данные нельзя, поэтому связь — своя коллекция `links` (id = id заметки, `exports`): события, ближайшее
  время, `done/doneAt`. «Сделал» (событие, блок, последний блок задачи, «Выполнено») → `markNoteDone`; «Заметки» читают
  `links` и закрывают дело сами. Дело, снова открытое там после отметки (`planDoneSeen` = `doneAt`), опять видно здесь.
- **Источники** (`lib/sources.ts`): `kv.get("profile", …, { from: "fit" })`, `roadmap` + коллекция `days` из devpath,
  коллекция `habits`. Владельцы открывают их в `exports`. Чужие данные читаются поле за полем — формат может меняться.
  Новый источник: добавить в `SOURCES`, разрешение `read:<id>` сюда и `exports` в модуль-владелец.
- **Голосовой ввод** — `useDictation` в `components/input.tsx`: распознавание речи браузера (Web Speech API, `ru-RU`).
  Работает в Chrome/Edge/Safari и только в защищённом контексте (localhost или HTTPS через Tailscale/ngrok);
  по http в локальной сети браузер его не даёт — показываем подсказку. Поля ввода растут с текстом (`AutoTextarea`).
- Фото запроса загружаются в файлы модуля (разрешение `files`) — так нейронка получает их по id и они видны в истории.
- Стиль: тёмный «ночной» (`theme: "dark"`), классы `pl-*` в `src/styles.css`, шрифт Onest, градиент фиолетовый → розовый.
  Цвета категорий — `CATEGORIES` в `lib/types.ts` (там же `colorId` Google).
